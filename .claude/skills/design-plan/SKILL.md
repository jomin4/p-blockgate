# 설계 문서 작성 (워크플로우 4단계, G2)

## 절차

1. **파일 생성**: `docs/plans/_TEMPLATE.md`를 복사해 `docs/plans/<이슈번호>-<slug>.md` 작성 (slug는 영문 소문자·하이픈).
   - 이 시점에는 main 작업 트리에 **커밋하지 않은 상태**로 둔다 (G2 후 브랜치에서 첫 커밋).
2. **AC 작성**: WHEN/THEN 형식. THEN에는 **구체적인 기대값**(숫자, 정확한 메시지 문구, 상태)을 쓴다.
3. **테스트 리스트 작성** (Canon TDD 1단계)
   - 각 AC마다 해당되는 종류를 모두: 정상 / 실패·예외 / 경계 / 권한 / MC 특수(접속 종료, 인벤토리 가득, 재시작 후 유지)
   - 항목 1개 = 동작 1개. 쉬운 것부터 어려운 순으로 정렬.
   - 레벨은 `docs/04-tdd-testing.md` 3장 결정 순서로 고른다. E2E는 핵심 흐름만.
   - 15개를 넘으면 이슈 분할을 제안한다.
4. **설계 메모**: 구조(순수 로직/Bukkit 분리), 명령어·권한, DB(Flyway 버전), 설정, 로그, 리스크, 플레이테스트 포인트.
5. **G2 요청**: 개발자에게 요약을 보여준다.

| AC | WHEN | THEN |
|---|---|---|

| T | 시나리오 | 레벨 |
|---|---|---|

   "이 설계로 진행할까요? 바꿀 점이 있으면 말해주세요."
6. **수정 반복**: 피드백을 반영해 다시 보여준다. 명시적 승인 전에는 구현하지 않는다.
7. **승인 후**: 문서 상단 상태를 `G2 승인 (날짜, 승인자)`로 바꾸고, 이슈에 "G2 승인" 코멘트(AC·테스트 리스트 요약 포함)를 남긴 뒤 `tdd-cycle` 스킬로 넘어간다.

## G2 재승인이 필요한 경우
- 구현 중 기대값·AC가 틀렸다고 판단될 때 → 멈추고 이유를 보고 → 문서 "변경 이력"에 기록 → 다시 승인.
