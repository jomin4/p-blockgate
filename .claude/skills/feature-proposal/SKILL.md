# 기능 제안 → 조사 → 방안 제시 (워크플로우 1~2단계, G1)

## 절차

1. **요구 정리**: 제안을 1~3줄로 다시 말해 확인한다. 꼭 필요한 질문만 최대 2개 묻는다 (범위·대상 플레이어 등).
2. **분류**: 버그면 `bugfix`, 이미 진행 중인 이슈와 겹치면 그 이슈를 알려준다 (`gh issue list --state open`).
3. **조사 위임**: `researcher` 서브에이전트에게 제안 원문 + 정리한 요구사항을 넘긴다.
4. **방안 제시**: 결과를 아래 형식으로 보여준다.

| 방안 | 방식 | 장점 | 단점 | 난이도 | 영향 영역 |
|---|---|---|---|---|---|
| 1 | | | | S/M/L | plugin/server/... |

   - **추천**: 방안 N — 이유 한두 줄
   - 큰 기능이면 이슈를 나눌 단위도 제안한다 (테스트 리스트 15개 이하 기준).
5. **G1 대기**: "어떤 방안으로 갈까요?"라고 묻고 **명시적 선택**을 기다린다. 선택 전에는 이슈를 만들지 않는다.
6. **다음**: 선택되면 `issue-create` 스킬로 넘어간다 (선택 방안과 이유를 함께 전달).

## 금지
- G1 전에 코드·브랜치·이슈를 만들지 않는다.
- 버전 업그레이드, 무료 한도 초과, 보안 원칙 위반이 필요한 방안은 제시하지 않는다 (필요하면 그 사실을 설명).
